Este documento resume la planificación elaborada en el desafío anterior de **Portafolio virtual**, cuyos elementos se incorporan ahora a la prueba final.

## 1. Selección del repositorio

Se seleccionó **GitHub** porque permite concentrar código, documentación, historial de cambios y vínculos hacia demostraciones o resultados. Los README facilitan explicar el problema abordado, las herramientas utilizadas, la metodología y los principales resultados sin exigir que el evaluador revise primero todo el código.

## 2. Referencia de portafolio

Como referencia se utilizó el portafolio de Brittany Chiang. Se identificaron como fortalezas una presentación profesional clara y una navegación sencilla por secciones. Para el propio portafolio se decidió reforzar el contexto metodológico de cada proyecto, indicando datos, herramientas, decisiones técnicas, métricas y limitaciones.

## 3. Prueba seleccionada

La prueba escogida como evidencia principal fue **Reconocimiento de imágenes con redes neuronales convolutivas**. La selección se justificó porque permite mostrar un flujo completo de trabajo con datos: preparación, transformación de 64 variables de píxeles a imágenes de 8 × 8, normalización, entrenamiento de una CNN, evaluación con métricas y matriz de confusión, y optimización del modelo.

Las mejoras definidas para su incorporación al portafolio fueron:

- conservar separación entre entrenamiento, validación y prueba;
- usar semilla fija para favorecer reproducibilidad;
- mostrar comparación antes/después;
- agregar una ficha inicial con objetivo, tecnologías, datos, resultado principal y limitaciones;
- mantener el código revisable desde el propio repositorio.

## 4. Perfil planificado

El perfil debía responder quién soy, de dónde soy, a qué me dedico, cuál es mi formación, cuáles son mis experiencias previas y cómo contactarme. Esta información se encuentra publicada en el README principal del portafolio.

## 5. Buenas prácticas definidas

- seleccionar pocos proyectos bien explicados;
- explicar problema y resultado;
- documentar para reproducir;
- cuidar privacidad, credenciales y datos sensibles;
- mantener una presentación consistente;
- revisar periódicamente enlaces y dependencias;
- mostrar proceso, decisiones, errores, limitaciones y mejoras.

## 6. Aplicación en la prueba final

La prueba final no se limita a repetir esta planificación. El repositorio actual la lleva a ejecución: incorpora el perfil, organiza los proyectos, publica código y documentación, y presenta la prueba CNN con las mejoras definidas previamente.
